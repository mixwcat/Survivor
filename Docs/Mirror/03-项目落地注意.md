## 2. 组合根与 `NetworkManager` 的归属

**项目约定**：全局服务（`IAssetService`/`IAudioService`/`IUIService`/`IPlayerProfileService`/`IRunSessionService`）
一律由组合根 `GameBootstrap` 创建、注册、初始化，挂在 `[GameBootstrap]` 对象上（`DontDestroyOnLoad`）。

`NetworkManager` 属于同一类「全局设施」，**应当照同一套来**：

- 由 `GameBootstrap.Boot()`（`RuntimeInitializeOnLoadMethod(BeforeSceneLoad)`）创建到 `[GameBootstrap]` 上；
- **不要**在每个场景里各摆一个 `NetworkManager`（重复实例 → Mirror 会销毁后一个，且服务入口会在切场景时断掉，与
  `ManagerSingleton` 的"重复实例覆盖服务"是同一类事故）；
- 不用 Mirror 自带的 `NetworkManagerHUD`（除临时调试），联机 UI 走项目自己的 `IUIService` + 面板；
- `NetworkManager.singleton` 是 **static**，关掉 Domain Reload 后会跨 Play 存活 →
  必须在 `GameBootstrap.ResetStatics()` 里一并清理（与 `ServiceLocator.Clear()`、`EnemyPool.Reset()` 同批）。

⚠️ **Host 模式下服务端与客户端在同一进程**：静态单例、`ServiceLocator`、C# `event` 是**共享**的。
于是同一个 `PlayerManager` / `GameLevelManager` 会同时被"服务端逻辑"和"客户端逻辑"读到。
不要用「客户端不会跑这段」来保证某段只执行一次 —— 必须显式区分权威与表现。

### ⚠️ DDOL 里**不能**放 `NetworkBehaviour`

Mirror 判断"是不是场景对象"用的是 `sceneId != 0`（`Assets/Mirror/Core/Tools/Utils.cs:90-103`）。
`[GameBootstrap]` 这类 `DontDestroyOnLoad` 对象 `sceneId == 0` ⇒ 被当成**动态生成对象**，
`NetworkServer.SpawnObjects()` 根本不遍历它（那函数只处理场景对象）⇒ `netId` 恒为 0 ⇒
`[Command]` / `[ClientRpc]` / `[SyncVar]` **全部静默失效**，且 `isServer`/`isClient` 恒为 false。

所以跨场景的"系统级"组件一律用 **纯 C# / `MonoBehaviour`**：
需要对外收发就用静态的 `NetworkServer.SendToAll(msg)` / `conn.Send(msg)`（不需要 `NetworkIdentity`），
需要 `[Command]` 就把它写在**玩家对象**（动态 Spawn 的对象）上的 `NetworkBehaviour` 里。

**例外**：`NetworkManager` 本身可以放 DDOL —— 它不靠 spawn 工作，自己 `InitializeSingleton()` + `DontDestroyOnLoad`（`NetworkManager.cs:699-718`）。

## 3. 未激活 prefab 与 Mirror 的强制 `SetActive`

**项目事实**：`Assets/Game/Prefabs/Common/Player.prefab` 的**根节点 `Player` 在资产里是未激活的**
（`m_IsActive: 0`，子节点 `Sprite` 是激活的）。这是刻意的：

> `PlayerSpawner` 在 `Instantiate` 之后、**激活之前**注入角色的 `playerConfig`；
> 顺序反了 `Awake` 会先按"没有配置"失败一次，之后 `SetEntityBehaviour.SetEntityConfig` 会被拒绝，
> 血量上限/移速停在 `1f` 兜底值（且只有一条告警）。

**冲突点**：`NetworkServer.Spawn()` 内部会无条件 `identity.gameObject.SetActive(true)`
（`Assets/Mirror/Core/NetworkServer.cs:1766`），`SpawnObjects()` 也会先激活场景对象（`:1645`）。
`AddPlayerForConnection` → `Respawn` → `Spawn`，同样会走到那一行。

**正确顺序（不可颠倒）**：

```csharp
GameObject go = Instantiate(prefab);          // 仍是未激活
InjectCharacterConfig(go, definition);        // 注入 playerConfig / role / loadout
go.SetActive(true);                           // 自己激活，Awake 此时才跑
NetworkServer.AddPlayerForConnection(conn, go); // 或 NetworkServer.Spawn(go)
```

**不要**依赖 Mirror 帮你激活 —— 那样注入就晚了。凡是"装配方注入后才激活"的 prefab
（Player、武器、塔、Boss 敌人），走 Mirror 生成时都要显式保持这个顺序。

## 4. `assetId` 与 `spawnPrefabs`

Mirror 靠 `NetworkIdentity.assetId` 在两端把 `netId` 还原成 prefab。规则：

1. **每个会被 `NetworkServer.Spawn` 的 prefab 都必须出现在 `NetworkManager.spawnPrefabs` 里**
   （玩家 prefab 单独放 `playerPrefab`）。漏了 → 客户端收到 `SpawnMessage` 时报
   `Failed to spawn server object, did you forget to add it to the NetworkManager?`。
2. **编程式（批处理）改 prefab 不会触发 assetId 分配**，`_assetId` 仍是 0。
   对策：保存后重新 `AssetDatabase.LoadAssetAtPath<GameObject>(path)`，
   **读一次 `ni.assetId` getter**（编辑器下会触发 `SetupIDs/AssignAssetID`），再 `EditorUtility.SetDirty` + `SaveAssets`。
3. `spawnPrefabs` 里**重复条目会导致 assetId 冲突**，Mirror 会在 `Awake`/`OnValidate` 报错。
4. 运行时注册 `NetworkClient.RegisterPrefab(prefab)` 可行，但**必须在收到对应 `SpawnMessage` 之前**完成，
   且服务端也要能解析同一个 assetId。用 Addressables 异步加载后再注册，等于把"注册完成"变成一个竞态 ——
   **不推荐**。

### 与「资源一律走 Addressables」的关系

- 同一个 prefab 既在 Addressables 组里、又被 `NetworkManager.spawnPrefabs` 强引用，
  **不会重复打包**（同一资产），只是后者让 prefab 进构建并常驻内存。
  这是 Mirror 的硬性要求，接受它。
- 玩家 prefab 想继续走 Addressables（保持"按需加载 + 注入后激活"）：
  **关掉 `autoCreatePlayer`，重写 `OnServerAddPlayer`**，自己 `LoadAssetAsync` → `Instantiate` → 注入 → 激活
  → `NetworkServer.AddPlayerForConnection(conn, go)`。这条路可行且推荐。
- 其余 spawn prefab（敌人/投射物/塔/经验球）建议**静态注册**（`spawnPrefabs` 直接引用），
  别为了 Addressables 把 assetId 解析变成运行时竞态。

## 5. 对象池 vs Mirror 生命周期（必须二选一）

项目现有三套静态池：`EnemyPool`、`ProjectilePool`、`ExpSpritePool`（外加 `ObjectPool` 基类）。
它们靠 `SetActive(false)` 复用，**从不销毁**。

Mirror 的生成对象由 `NetworkServer.Destroy` 销毁并广播 `ObjectDestroyMessage`，客户端会销毁本地实例。
**两套生命周期不能叠加**：

- 池化复用不会重新 `Spawn` → 客户端不会重建该对象；
- Mirror 的 `Destroy` 会真的销毁实例 → 池里留下伪 null。

**结论：联机路径下关闭池化**（敌人、投射物、经验球都走 `NetworkServer.Spawn/Destroy`）。
纯本地表现（伤害数字、特效）继续用池。

连带影响：

- `AttackDriver.Spawn/Despawn`（`IAttackSpawner`）是**设计好的替换点** ——
  联机实现换成 `NetworkServer.Spawn` / `NetworkServer.Destroy`，`AttackMethodSO` 完全不受影响。
- `AttackDriver.OnDestroy` 里的 `ProjectilePool.RetainsInstancesOf` / `DropPool` 分支在联机路径下不再需要。
- `EnemySpawner` 的"Boss 不走池 / 小怪走池"分支要按端分流（见 `EnemyHealthController.UsePool`）。
- `GameBootstrap.ResetStatics()` 里的 `EnemyPool.Reset()` / `ProjectilePool.Reset()` / `ExpSpritePool.Reset()`
  **保留**（单机路径与编辑器仍要它们）。

## 8. 时序：不要赌 `Awake`/`Start` 顺序

现有约定（`CLAUDE.md`）：

- `GameBootstrap` 由 `RuntimeInitializeOnLoadMethod(BeforeSceneLoad)` 创建，服务异步初始化；
  场景脚本 `await GameBootstrap.TryWaitReadyAsync()` 之后再推进。
- 场景级 Manager 用**负** `[DefaultExecutionOrder]`：`PlayerManager(-130)`、`GameLevelManager(-120)`、
  `EnemyTargetRegistry(-110)`。
- `EntityBehaviour.Awake` 建 `StatModel`；子类在 `base.Awake()` 之后可安全用。
- 需要"服务就绪"的 `Start` 用 `async void` + `await`，**续体首行必须判 `this == null`**（切场景）。

**联机新增的时序陷阱**：

- `NetworkBehaviour.Awake` **早于** `OnStartServer` / `OnStartClient`，此时 `isServer` / `isClient` **还没设置** ——
  不要在 `Awake` 里做网络分支判断（会永远走 `else`）。
- 客户端收到 `SpawnMessage` 时，**目标场景可能还没加载完**；`OnStartClient` 里不要依赖
  `UIService` / Addressables 已就绪。需要就自己 `await GameBootstrap.TryWaitReadyAsync()`，
  但要包成 `async void` 并在续体首行判 `this == null`。
- `NetworkManager.OnServerAddPlayer` 可能早于场景脚本的 `Start`（客户端连上就 AddPlayer）——
  凡是"玩家生成后才存在"的场景引用（相机目标、HUD）都要能容忍"先来后到"，
  用事件（`PlayerManager.LocalPlayerChanged`）而不是在 `Start` 里 `FindFirstObjectByType`。
- `[SyncVar]` 的 hook 在客户端**初次同步时也会调用**（`oldValue` 是默认值），
  所以 hook 里不能假设"这是变化"，也不能假设对象已经初始化完毕。
- 场景对象的 `NetworkIdentity` 在服务端 `SpawnObjects()` 之前是**禁用**的（Mirror 的 `NetworkScenePostProcess`）——
  不要用 `FindFirstObjectByType` 在 `Awake` 里找它们。

## 9. 场景流：`SceneFlow` 是唯一入口

`Core/SceneFlow.cs` 是全项目**唯一**的切场景入口（写 `SceneManager.LoadSceneAsync` + 复位 `Time.timeScale`）。

联机改造要点：

- 服务端切场景必须走 `NetworkManager.ServerChangeScene(name)`；
  **客户端不要自己 `LoadScene`** —— 那会和 Mirror 的场景同步打架，出现"两端场景不一致"。
- `SceneFlow` 应改成"按当前网络角色分派"：服务端 → `ServerChangeScene`，客户端 → 什么都不做（等服务端）。
- `Time.timeScale = 1f` 的复位**必须保留**（跨场景全局状态，带着 0 进下一个场景看起来像卡死）。
- `NetworkManager.onlineScene` / `offlineScene` 与 `Menu`/`Lobby`/`Level0` 的对应关系**已定死**（见 `../MirrorPlan.md` §1.3）：
  `Menu` = 纯离线标题页；**`Lobby` = 房间 + 离线大厅**（`offlineScene`）；`onlineScene` **留空**。
  ⚠️ 由此产生一条容易踩的推论：`onlineScene` 留空 ⇒ `IsServerOnlineSceneChangeNeeded()` 恒 false
  （`Core/NetworkManager.cs:280-283`）⇒ 在 Lobby 里 `StartHost()` **不会切场景**，直接走 `FinishStartHost()`。
  这条路径下 `NetworkServer.SpawnObjects()` 仍会跑（`NetworkManager.cs:563`），但
  **`OnServerSceneChanged` 不会被调用** —— 生成玩家要用 `OnServerReady(conn)` / `OnStartServer`。

## 10. 暂停与 `Time.timeScale`

`GameLevelManager.ApplyPauseState()` 直接写全局 `Time.timeScale = 0f`。
联机下这会**冻结本进程的一切**（包括网络对象的本地表现与插值），而**服务端进程照常在跑** ——
玩家会看到"我暂停了但队友还在打、怪还在动"。

处理方式（M5 决策点）：

- 联机下**禁止面板写 `Time.timeScale`**（暂停改为纯 UI 覆盖层 + 屏蔽本地输入）；或
- 只在"单人 Host"时允许真暂停；
- 断线/重连后 `Time.timeScale` 必须是 1。

## 11. 相机

`Level0` 场景里**已经没有 Player 节点**（由 `PlayerSpawner` 运行时生成），
`CinemachineCamera` 的目标必须在运行时绑定。

- 绑定对象必须是**本地玩家**（`NetworkIdentity.isLocalPlayer`），不是"第一个玩家" ——
  Host 下同时存在本地与远程玩家，取错就跟错人。
- 绑定时机走 `PlayerManager.LocalPlayerChanged`，不要靠 `Start` 里的 `FindFirstObjectByType`。
- 玩家死亡/重生成时相机要能重新绑定（`LocalPlayerChanged` 会再发一次）。

## 12. 输入

- `InputHandleFactory` 已预留 `network_X` 分支，当前返回 `NullInputHandle` + 一条告警（**刻意不回落本地输入**）。
- **客户端权威移动**下，只有 `isLocalPlayer` 的 `PlayerController` 读输入；其余实例必须是零输入。
- `PlayerController._inputHandleId` 是**序列化字段**、默认 `"local"` ——
  Host 下两个玩家实例都默认 `"local"`，会**共享同一个句柄**（远程角色跟着本地输入动，且不报错）。
  必须在运行时按实例改写 id（例如 `local` / `remote_<netId>`）。
- Android：`InputHandleFactory.CreateLocalInput()` 用 `FindObjectsByType<Joystick>()` 取前两个摇杆，
  **无法区分玩家** —— 多玩家同屏时要么一人一设备，要么改成按玩家分配摇杆。
- `PlayerController.Update` 采样输入、`FixedUpdate` 消费（刻意的：物理帧 50Hz 会漏掉轻按）——
  这个分工在联机下保持，但采样前要加 `isLocalPlayer` 守卫。

## 13. UI / 音频 / 伤害数字（纯本地，不要被 Rpc 污染）

- `UIService` / `AudioService` / `DamageNumService` / `PlayerHudBinder` **只在本地跑**。
- 面板（升级三选一、选塔、武器升级、暂停、结算）只作用于 `LocalPlayer`。
- ⚠️ `BaseHealthController.Heal()` 内部直接调 `DamageNumService.Service?.SpawnDamageNum(...)`
  （`Entity/Common/BaseHealthController.cs:152`）。血量一旦改成服务端结算，
  这条调用会在**服务端进程**里跑（无画布，静默无效），而客户端看不到数字。
  要么把治疗表现改成广播事件，要么只在本地结算路径上调它。
- 同理 `BaseHealthController.TakeDamage` 的伤害数字、死亡特效、音效都要走"权威结算 + 本地表现"两段。
- 结算面板 `RunResultPanel` 由服务端判定后 `ClientRpc` 触发，奖励数值以服务端下发的 `RunResult` 为准。

## 14. 物理与权威

- 敌人 / 推车 / 塔在**服务端**模拟；客户端上的这些实例应停止 AI 与物理（位置完全由 `NetworkTransform` 驱动），
  否则本地物理会和同步位置互相打架（抖动 / 漂移）。
- `PlayerController.FixedUpdate` 直接写 `rb.linearVelocity` ——
  客户端权威时本地玩家正常；**远程玩家的实例必须跳过**，否则远程角色的位置会被本地物理覆盖。
- `EnemyController.FixedUpdate` 的寻敌/移动、`EnemyTargetFinder` 的选目标、
  `EnemyHealthController` 的接触周期伤害都必须在**服务端**跑。
- `NetworkTransform` 与 `Rigidbody2D` 同时存在时要明确谁是权威：
  **服务端模拟的对象**（敌人 / 推车 / 塔）用 `syncDirection = ServerToClient`，客户端把 `Rigidbody2D` 设为 `Kinematic` 或直接禁用；
  **玩家**是客户端权威（见 `../MirrorPlan.md` D1），必须用 `syncDirection = ClientToServer`。

## 15. Weaver / Domain Reload / 本地补丁（升级 Mirror 时要重贴）

已知坑（来自 `.claude/skills/unity-batch-autoconfig/SKILL.md`）：

1. **编程式改 prefab 不触发 `assetId` 分配** —— 见第 4 节。
2. **`AddComponent<NetworkTransform>()` / `NetworkRigidbody2D` 会触发 `Reset()` NRE** ——
   噪声，组件仍会加上；随后显式设置 `target`、`syncDirection`、`updateMethod` 等即可。
3. **Unity 6 进 Play 的 domain reload 会序列化带 `NetworkIdentity` 的 prefab**，
   触发 Mirror `NetworkConnection()` 里的 `Time.time` →
   `UnityException: get_time is not allowed to be called during serialization`。
   ⚠️ **当前源码里还没有这道补丁** —— `Assets/Mirror/Core/NetworkConnection.cs:61-66` 仍是裸的
   `lastMessageTime = Time.time;`。对策是在该构造函数里 `try/catch` 回退为 0
   （**本项目的第一件事，见 `../MirrorPlan.md` 的 P0.3；升级 Mirror 后要重贴**）。
4. **`NetworkBehaviour` 没有 `NetworkIdentity` 会在编辑器 `OnValidate` 报错** ——
   凡是把某个基类改成 `NetworkBehaviour`，其**所有子类**所在 prefab 都要在**根节点**有 `NetworkIdentity`。
5. **Mirror `SpawnMessage` 不含父子关系** —— 不要指望"服务端 `SetParent` 后 `Spawn`，客户端自动跟随父子"。
   要么客户端在 `OnStartClient` 自行重建父子，要么服务端算好世界坐标用 `NetworkTransform` 同步。
   （本项目的武器实例挂在 `WeaponMount` 下、环绕物挂在武器下 —— 都是这条的适用场景。）

## 16. 批处理配置与验证

- **必须先关 Unity 编辑器**：GUI 占用工程时批处理直接崩溃（`another Unity instance is running`）。
  ⚠️ 当前机器上有 Unity 进程在跑，动代码前先确认。
- `csc` 离线编译**不跑 Weaver** —— 最终必须有一次 Unity 内的编译（批处理 setup 会触发）。
- 批处理只能验证"编译 + Weaver + 资源接线"，**运行时表现必须由人 Play 确认**，不要声称"功能已验证"。
- 脚本化接线场景对象时用 **public 字段直接赋值**，不要走 `SerializedObject`
  （实测场景里组件的对象引用写不进去；prefab 上用 `PrefabUtility.LoadPrefabContents` + `SerializedObject` 可靠）。
